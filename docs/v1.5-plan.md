# v1.5 plan — the relationship layer

Scope: a local extension of the submitted v1. One command to run, SQLite, zero keys
required, no new dependencies, no AWS. Machine twin: `docs/v1.5-dag.yaml`. `DESIGN.md`
stays the source of truth for everything v1; this file is the source of truth for what
v1.5 adds. Where the two disagree, this file wins for v1.5 only.

## What v1.5 is, in four sentences

Today the app knows one fact per company: its peers. v1.5 stores a short list of typed
facts per company (competitors, suppliers, customers, countries, and price-derived factor
betas), and a small table of dated geopolitical headline counts per country. It uses them
in exactly two places: routing (a move gets a `sub_routing` such as `share_shift`,
`supply_chain`, `oil`, `country:TW`) and retrieval (the news query expands along the
edges). One gate rule stops geopolitical headlines from being credited unless the company
has the country edge and the country's factor actually moved that day.

## Decisions (each one is a DESIGN-style rule an agent can code against)

1. **Edges are one table.** `company_edges(src, dst, relation, weight, source, updated_at)`,
   primary key `(src, dst, relation)`. `relation` is one of `competitor`, `supplier`,
   `customer`, `country`, `factor`. `dst` is a ticker for the first three, an ISO-3166
   alpha-2 code for `country`, and a factor name (`oil`, `dollar`, `rates`, `gold`) for
   `factor`. `source` is `model`, `etf_holdings`, or `prices`.
2. **Competitor replaces peer, it does not sit beside it.** `companies.peers_json` stays for
   backward compatibility and is now the ETF fallback for `competitor` edges. There is one
   concept in code: `relation == "competitor"`. `peer_comove` keeps its name and meaning.
3. **Model-suggested edges are stamped as such.** One provider call per company,
   `suggest_relations`, returns competitors, suppliers, customers, and countries with
   weights. The heuristic provider returns competitors from ETF holdings and nothing else.
   So without a key the geopolitical gate can never open. That is the honest behaviour and
   the write-up says so.
4. **Factor exposure comes from prices, not the model.** Proxies: `USO` (oil), `UUP`
   (dollar), `TLT` (rates), `GLD` (gold), plus one country ETF per country edge from a
   static dict (`EWT`, `FXI`, `EWJ`, `EWY`, `INDA`, `VGK`, `EWW`, `EWC`, `EWU`, `EWG`).
   The SPY plus sector OLS that drives `routing` is unchanged. Attribution is a second,
   separate step: per proxy, a trailing 60-day univariate beta of the stock on the proxy;
   the day's contribution is `beta * proxy_ret`; the `macro_driver` is the proxy with the
   largest absolute contribution among proxies whose own return that day has
   `abs(z) >= 1.5` on a 20-day window. If no proxy moved, the driver is `None`. This is a
   heuristic, not a joint model, and is documented as one.
5. **Geopolitical events are headline counts, not GDELT Events.** The GDELT Events CSV feed
   is 96 files a day and out of scope; the DOC API cannot filter by CAMEO code. So a geo
   event is `geo_events(date, country, headline_count, sample_titles_json, news_source)`,
   built by querying the existing `NewsSource` with `"<country name>" (tariff OR sanctions
   OR "export controls" OR ban OR embargo OR conflict OR war)` over the move window, only for
   countries in the company's edges, only when a move exists. No new API, no throttle
   beyond the one v1 already has.
6. **Routing keeps three buckets and gains a sub-bucket.** `routing` stays
   `company|industry|macro`. New `sub_routing` on `moves`:
   - `share_shift`: routing is `company` and competitors moved the opposite way
     (`rival_comove * sign(ret) <= -0.25 * abs(ret)`, at least two competitors with data).
   - `supply_chain`: routing is `company` and suppliers or customers moved the same way
     (`chain_comove * sign(ret) >= 0.5 * abs(ret)`).
   - `oil|dollar|rates|gold|country:XX`: routing is `macro` and `macro_driver` is set.
   - `None` otherwise. Thresholds are module constants in `moves.py`.
7. **The gate rule.** An article that matches the geo vocabulary is capped at relevance
   `0.30` unless both hold: the title names a country the company has a `country` edge to,
   and the move's `macro_driver` is `country:XX` for that country or one of `oil|dollar`.
   Both or nothing. Implemented as a post-hoc cap in `scoring.heuristic_components`, stored
   as component `geo_gate` (1.0 open, 0.0 closed, `None` not applicable).
8. **Retrieval expands along the edges.** `share_shift` adds one query per competitor that
   moved the opposite way: `"<rival name>" stock`. `supply_chain` adds one per supplier or
   customer that moved. `country:XX` adds the geo query from decision 5. Cap: three extra
   queries per move.
9. **Prose.** An explanation can now say `macro, geopolitical, via Taiwan exposure` or
   `share shift: AMD up the same day`, citing the geo event and the headline. The heuristic
   templates the same sentence.
10. **API stays the same, plus one read.** `move_to_dict` gains `sub_routing`,
    `macro_driver`, `macro_driver_component`, `rival_comove`, `chain_comove`.
    `GET /tickers/{ticker}/relations` returns the edges. Chat gains the `get_relations` tool.
11. **Fixes first.** Before any of the above: a working key proven by one live call, default
    period `2y` so regimes fill in, and heuristic confidence that requires an event verb in
    a cited headline. These are the three the write-up promised.
12. **Deployment stays as v1 left it.** The Vercel path seeds from `data/snapshot.db.gz`;
    the snapshot is rebuilt at the end of v1.5 with the new columns. No scheduled jobs.

## Eval set: decide before build, check after

Three ticker-days, each with an expected `sub_routing`. The returns must be confirmed in the
ingested data before any of these are treated as ground truth; the dates are from memory.

| ticker | date | what happened | expected routing | expected sub_routing |
|---|---|---|---|---|
| NVDA | 2025-04-16 | export-licence requirement on H20, $5.5B charge | company or macro | `country:CN` if macro, else `None` with a geo citation |
| NVDA | 2025-01-27 | DeepSeek day, chip names down together | industry | `None` (industry has no sub-bucket) |
| AAPL | 2025-04-03 | tariff announcement, the day after 2025-04-02 | macro | `country:CN` or `dollar` |

Pass means the stored `sub_routing` matches and at least one cited article names the event.
`scripts/eval_v15.py` prints all three and exits non-zero on a mismatch. It uses the network
and is not part of pytest.

own files; no two tasks in one wave own the same file.
